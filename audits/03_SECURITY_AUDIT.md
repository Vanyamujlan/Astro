# 03. Аудит безопасности (Security Audit)

> **Назначение документа:** контроль защиты секретов, платёжной логики, прав доступа и устойчивости к злоупотреблениям.  
> **Критическое правило:** НИКОГДА не записывать в этот или любой другой файл аудита реальные API-ключи, токены, пароли, приватные данные пользователей или ID чеков.

| Вектор угрозы | Запланированная защита | Целевой файл (план) | Статус |

## 4. Безопасность данных и резервное копирование

- [ ] **SQLite WAL и консистентность бэкапов:** использование `sqlite3.Connection.backup()` вместо прямого копирования файла БД (`src/scheduler/backup.py`).
- [ ] **Безопасное форматирование для Telegram:** экранирование пользовательского ввода (имён, названий городов) перед вставкой в HTML/MarkdownV2 сообщения (`src/utils/text_helpers.py`).
- [ ] **Защита от SQL-инъекций:** использование исключительно параметризованных запросов SQLAlchemy ORM.
